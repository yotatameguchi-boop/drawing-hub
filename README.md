# Drawing Hub — 建築図面のレビュー基盤

紙で描いた図面を取り込み、**版（Rev.）を重ねて比較**し、**図面上の位置を指した指摘**と
**全員で書き換えられる赤入れレイヤー**で検図するツール。単一 HTML ファイルの Claude Artifact として動きます。

公開先: <https://claude.ai/code/artifact/62548467-785f-48d4-a266-2c36d674377b>
使い方ガイド: <https://claude.ai/code/artifact/26bfd326-e5f4-45a3-af4f-055464f033b2>（`guide.html`）

## 画面構成

ダッシュボード型をやめ、**ボタンを押すと機能ごとの画面に遷移する**構成です（スマートフォンでの現場利用が主目的のため）。

```
ホーム（プロジェクト＋図面一覧）
 └ 図面ハブ（プレビュー＋機能ボタン）
     ├ 指摘事項 → 指摘詳細 → 指摘を追加
     ├ 図面を見る（拡大・ピン・指摘を打つ）
     ├ 赤入れ / 版を比較 / 3Dパース / AI検図
     ├ 版を追加（撮影・画像・PDF・SVG・3Dモデル）
     └ 関連図面 / 検図結果 / 版の履歴
ホーム → 発行セット → 図面目録
```

各画面は独立したスクリーンとして `SCREENS` に登録され、`go()` / `back()` の履歴スタックで遷移します。
下部に固定のタブ（ホーム／図面／指摘／設定）があり、階層を一段で行き来できます。

見た目は GitHub モバイルのグループ化リストに寄せています。薄いグレー地に角丸16pxの白いカード、
カードの外に大きなセクション見出し、行は「色付きアイコンタイル＋見出し＋補足＋シェブロン」、
区切り線はアイコン幅ぶん内側から。アイコンの色は分野（意匠=紺／構造=橙／設備=緑／外構=青緑）と
機能で塗り分けています。

## できること

| 機能 | 内容 |
| --- | --- |
| 原図の取り込み | カメラ撮影 / 画像 / PDF / SVG。撮影画像は四隅を指定して**台形補正**、**白飛ばし・線画化**で紙の影を除去 |
| 3D / パース | GLB・glTF を登録すると、同じ図面カードの中で **図面 ⇄ 3Dパース をワンボタンで切替**。パース／アイソメ、南東北西・上からの視点、モデル表面への指摘（アングルごと保存）、見ているアングルをパース画像として版に書き出し |
| 版管理 | Rev.A, B, C… と積み上げ、変更内容メモと登録者を記録。2Dの版と3Dの版は同じ図面にぶら下がる |
| 版の比較 | 単票 / 重ね（旧版=朱・新版=紺）/ ワイプ / 並べて。透過率と境界はスライダーで調整 |
| 指摘 | 図面上をクリックして起票。分類（意匠・構造・設備・法規）、状態（未対応・対応中・完了）、返信スレッド |
| 赤入れ | ペン・直線・引出し・矩形・雲マーク・文字。**他の人が描いた要素も選択・移動・修正・削除できる** |
| AI検図（Copilot） | 表示中の版の画像を Claude に読ませ、法規・納まり・整合・設備取り合いの観点で指摘候補を最大6件提示。**採用したものだけ**が指摘として起票され、同時に該当範囲へ改訂雲と件名が自動で描かれる |
| 改訂雲の自動生成 | 2つの版の画素差分から変更領域を検出し、その範囲に改訂雲を一括で打つ |
| 発行セット | ある時点の各図面の版を凍結して記録（GitHubのRelease相当）。宛先・発行日つき、図面目録をCSV出力、その版を開き直せる |
| 図面間の参照 | 「この図面はA-101に依存する」を登録。参照先に新しい版が上がると**「要確認」が自動で立つ** |
| 担当と期限 | 指摘に担当者と回答期限。自分宛・期限超過での絞り込み |
| 検図結果 | 承認 / 条件付承認 / 要修正 を所見つきで記録 |
| 書き出し | 指摘一覧を CSV（Excel 用 BOM 付き）で保存 |
| 公開範囲 | プロジェクト単位で「オープン」/「プライベート」 |

## 公開範囲の仕組み

アプリ内の表示上の区別ではなく、**保存先そのものを分けています**。

- **オープン** … `projects/**` に保存。このページを開ける人全員が閲覧・指摘できる
- **プライベート** … `vault/**` に保存。`vault` は `read: admin / write: admin` のルールを宣言しているため、
  「編集可」で共有された人以外にはサーバー側で存在しないものとして返る（図面も指摘も一覧に出ない）

切り替えると、図面・版・指摘・赤入れをまとめて保管領域ごと移送します。

## データ構造（Artifact の db capability）

```
projects/{pid}                                  … オープンなプロジェクト
vault/{pid}                                     … プライベートなプロジェクト（編集権限者のみ）
  └ drawings/{did}                              … 図面（図番・図名・分野・縮尺・検図結果）
      ├ revs/{rid}                              … 版（view: "2d" | "3d"、画像・モデルは assets の id を保持）
      ├ sets/{sid}   ※プロジェクト直下  … 発行セット（各図面の版のスナップショット）
      ├ marks/{mid}                             … 指摘（2Dは正規化座標 x,y／3Dはワールド座標 p とカメラ cam）
      └ edits/{eid}                             … 赤入れ要素（1 要素 1 ドキュメント＝同時編集に強い）
```

図面の画像・PDF・SVG は `assets` capability に保管し、ドキュメントには id だけを持ちます。

## 3Dモデルの扱い

Artifact の `assets` はバイナリの 3D 形式を直接受け付けないため、GLB/glTF は
`{format, name, b64}` の JSON にラップして `application/json` として保管し、
表示時に base64 を戻して three.js の `GLTFLoader.parse()` に渡しています。
このため実質 **約14MB までの GLB** が上限です。Draco 圧縮・KTX2 テクスチャは未対応。
three.js は jsDelivr から動的に読み込みます（3Dに切り替えたときのみ）。

## 制約

- 動作には Claude Artifact のランタイム（`db` / `assets` / `downloads`）が必要です。
  素の Web サーバーに置くと「未接続（閲覧のみ）」になります。GitHub はソース管理用です。
- 閲覧者の識別子を取れないため、投稿者は各自が入力した**表示名**で記録されます。
  承認の真正性が要る用途（法的な主張が必要な検図記録）には、本物の認証基盤が必要です。
- AI検図の結果は候補にすぎません。採用操作を経るまで記録には入らず、内容は人が確かめる前提です。
- 図面の実体（画像）は推測困難な URL で配信されます。プライベートでもドキュメント側でのみ id を秘匿します。
- PDF は pdf.js でページを画像化して取り込みます（元 PDF も併せて保管）。CAD 由来で
  フォントが埋め込まれていない PDF は文字が欠けることがあります。その場合は SVG 書き出しを推奨。

## 開発

単一ファイル `index.html`。ビルド不要。更新は Claude Code から同じ URL へ再公開します。
